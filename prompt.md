We are building an Autonomous Ride-Sharing Dispatch System in C as an Operating Systems project. Here is the full context:
What it is: A multi-process, multithreaded simulation of a ride-sharing backend split across two separate processes. Ride requests come in as threads (producers), drivers are shared resources (consumers), and a priority queue acts as the buffer between them. It is a producer-consumer problem with priority scheduling, timeouts, starvation prevention, and runtime configuration. The two processes communicate via named pipes (requests in) and shared memory (state out).
Language & Tools: 
Language: C
Threading: pthreads (pthread_mutex_t, pthread_cond_t, sem_t)
IPC: Named pipes (mkfifo) for request delivery, POSIX shared memory (shmget/shmat) + named semaphores (sem_open) for state broadcast
GUI: Raylib (runs in Request Server only)
Compiler: gcc on Linux/Ubuntu
Logging: plain file I/O (fprintf to .log file)
Configuration: config.txt parsed at startup or CLI args (--drivers, --duration, --surge-threshold, --timeout-normal, --timeout-vip, --timeout-emergency)
Two-Process Architecture:
Main Server: Owns all thread logic - Owns priority queue - Owns dispatcher - Owns metrics & logger - Owns shared memory writer

Request Server: Owns the GUI (Raylib) - Sends new requests (user/random) - Reads SharedState & renders it - Owns driver pool - Nothing else
Request Server → Main Server : PipeRequest struct via named pipe 
Main Server → Request Server : SharedState struct via shared memory
Core Flow: 
request_thread spawns, inserts into PriorityQueue (EMERGENCY > VIP > NORMAL), signals dispatcher via pthread_cond_signal, waits with pthread_cond_timedwait (timeout = per-category timeout_seconds from config). If timeout fires → status = CANCELLED → logged with request_id → thread exits.
dispatcher_thread wakes on not_empty signal, pops highest priority request, finds FREE driver (VIP drivers preferred for EMERGENCY/VIP requests). If no driver → re-inserts request → sleeps 500ms → retries. Before sleeping, calls age_waiting_requests() on all requests remaining in the queue: increments each request's wait_ticks, and promotes NORMAL→VIP after AGING_THRESHOLD_NORMAL_TO_VIP skips, VIP→EMERGENCY after AGING_THRESHOLD_VIP_TO_EMERGENCY skips, logging a PROMOTION event with request_id on each promotion, then rebuilds the heap. Marks driver BUSY → signals request thread → spawns ride_thread. After every state change, writes updated SharedState to shared memory under shm_lock.
ride_thread applies surge pricing if queue size > surge_threshold (from config), sleeps ride_duration, marks driver FREE, signals dispatcher (driver now available), updates metrics → logs COMPLETED with request_id. Writes updated SharedState to shared memory.
Request Server GUI loop reads SharedState from shared memory every frame under shm_lock and renders it via Raylib. User can submit a request manually (choosing type) or enable random generation. On submission, builds a PipeRequest and writes it to the named pipe. Main Server reads the pipe, promotes it to a full RideRequest, and inserts it into the queue.
Features: Priority scheduling: EMERGENCY > VIP > NORMAL. Request timeout & auto-cancellation (per category, timeouts loaded from config). VIP drivers preferred for high priority requests. Dynamic drivers randomly going ONLINE/OFFLINE (with GOING_OFFLINE transitional state — driver only goes OFFLINE after current ride ends, not mid-ride). Surge pricing when pending queue exceeds surge_threshold.File logging of all events (created, assigned, promoted, completed, cancelled) — every log line carries request_id so a single request's full lifecycle can be grepped. Starvation prevention via aging: each request carries wait_ticks (incremented each dispatch cycle it is skipped) and original_type (set at creation, never changed); upon promotion, type and priority are updated and wait_ticks resets to zero. Metrics printed to stdout at shutdown via metrics_report(): avg wait time per category (bucketed by original_type), driver utilization percentage, cancellation rate — human-readable summary for demo. All constants (num_drivers, timeouts, surge_threshold, aging thresholds, simulation duration) configurable via config.txt or CLI args, no recompiling needed. Live state (drivers, pending requests, metrics, log lines, surge status) broadcast to Request Server via shared memory after every state change
Constraints & Rules: No actual UNIX signals (SIGALRM) — timeouts handled via pthread_cond_timedwait. Dispatcher is a single dedicated thread — no concurrent dispatching. All shared state access is mutex-protected within Main Server. Shared memory access across processes protected by named semaphore shm_lock. Threads are detached where join is unnecessary (ride_thread). An active_rides counter (mutex-protected) is maintained so main() can wait for all in-flight rides to drain before calling metrics_report() and exiting — ensuring clean shutdown. GUI (Raylib) lives entirely in Request Server — Main Server has no GUI code. Request Server never writes to shared memory — only Main Server writes, Request Server only reads. Named pipe is one-directional: Request Server → Main Server only
